# 我是 OOP

## 前言

对初学者来说，”面向对象程序设计“更像一次从程序设计基础走向更规范、更抽象、更可扩展写法的过渡。学习这门课时，读者会先接触字符串、顺序容器、库算法、输入输出流等基础工具，再逐步进入类、运算符重载、继承、多态、模板和资源管理这些更核心的内容。因此，真正重要的不是零散记住几个语法点，而是逐渐建立一种更清晰的程序组织方式。

本资料面向第一次系统学习面向对象程序设计的初学者，目标是帮助读者用较自然的方式理解基础概念、常见语法和典型程序结构，并在之后继续学习类、继承、多态和模板时，有一个足够稳定的出发点。

---

## 第一章 从字符串到批量数据

### 本章概要

很多人刚接触 C++ 时，会把注意力全部放在“它和 C 语言哪里不一样”上。这种比较当然有帮助，但还不够。更重要的是看清楚：C++ 希望程序员更多地借助**标准库**来表达问题，而不是凡事都从头手写。字符串不再只是字符数组，若干个数据也不必只靠固定长度数组保存，输入输出也不仅仅是“读一个数、打印一个数”这么简单。正是从这些地方开始，C++ 的风格逐渐和更早的过程式写法拉开了距离。

这一章主要讲四件事。第一，认识 C++ 程序最基本的外形，例如头文件、名字空间、输入输出流和 `main` 函数。第二，学会使用 `string` 处理文本，而不是继续把“字符串”仅仅理解成一串字符。第三，学会在不知道数据个数时，把一批数据放进 `vector` 这样的顺序容器里。第四，借助标准库算法 `sort` 对数据排序，并进一步计算中值。读完这一章后，读者应当能够写出一个完整的小程序：从输入中读入名字和成绩，保存一批作业分数，排序后取中值，再按指定精度输出结果。

### 1.1 从 Hello, world 到第一个完整程序

最经典的 C++ 程序通常写成下面这样：

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!" << std::endl;
    return 0;
}
```

虽然代码很短，但它已经包含了后面会不断出现的几个基本对象。第一行 `#include <iostream>` 表示把标准输入输出流相关的声明引入当前程序。这里的 **头文件**（header）可以理解为“接口说明书”，它告诉编译器标准库里有哪些名字可以用。若不写这行，后面的 `std::cout` 和 `std::endl` 就没有合适的声明，程序通常无法通过编译。

`main` 是程序的入口函数。所谓入口，就是程序运行时首先从这里开始执行。函数头中的 `int` 表示这个函数返回一个整数，最后的 `return 0;` 通常表示程序正常结束。以后写更复杂的程序时，`main` 里往往会调用其他函数、构造其他对象，但“程序从 `main` 开始”这一点不会改变。

真正负责输出的是这一句：

```cpp
std::cout << "Hello, world!" << std::endl;
```

这里的 `std::cout` 是**标准输出流**（standard output stream），可以把它简单理解成“面向屏幕的输出通道”。右边的 `"Hello, world!"` 是一个字符串字面量，而 `std::endl` 的作用是结束当前这一行，并把缓冲区中的内容及时送出去。中间的 `<<` 叫作**输出运算符**，它把右边的内容送到左边的输出流中。

这一句之所以值得认真看，不只是因为它是第一条输出语句，更因为它体现了 C++ 的一个重要风格：把“输出”看成一个可以不断接收数据的流。例如下面这句同样合法：

```cpp
std::cout << "A = " << 3 << std::endl;
```

它的意思并不是“连续写了三条语句”，而是把多个输出动作串联在了一起。这里要特别注意：`<<` 在这种写法中是**左结合**的，也就是说程序会按从左到右的方式理解它。于是，这一整句等价于先把 `"A = "` 送进输出流，再把 `3` 送进去，最后再送一个换行结束符。

### 1.2 名字空间与 `std::`

初学 C++ 时，最容易反复看到的一个前缀就是 `std::`。它的含义其实并不复杂：`std` 是标准库使用的一个**名字空间**（namespace），而 `::` 是作用域解析运算符。写成 `std::cout`，就是在明确说明“这里说的 `cout` 来自名字空间 `std`”。

为什么要这样设计？因为大型程序中可能会出现大量重名。假如某个程序员自己也定义了一个叫 `cout` 的名字，而标准库里恰好也有一个 `cout`，那么编译器就会分不清到底在用谁。名字空间的作用，就是把相关名字装进不同的“抽屉”里，从而减少冲突。

刚开始写程序时，总是写 `std::cout`、`std::endl`、`std::string` 看上去有些繁琐，所以 C++ 提供了两种常见的简化方式。第一种是只引入少数常用名字：

```cpp
using std::cout;
using std::endl;
```

这样以后就可以直接写 `cout` 和 `endl`。第二种是

```cpp
using namespace std;
```

它表示把 `std` 里的所有名字都临时拿到当前作用域中。写起来确实更省事，但也更容易带来重名问题。因此，在入门阶段可以认识这种写法，但要知道它的本质是在“省略前缀”，而不是让 `std` 消失了。

### 1.3 `string`：把文本当成对象来处理

在更早的程序设计中，很多人第一次接触“字符串”时，是从字符数组开始的。C++ 标准库提供了 `string` 类型之后，文本处理就不必总依赖底层数组细节了。所谓 `string`，可以简单理解为：**用来保存零个或多个字符序列的对象**。它定义在头文件 `<string>` 中，因此使用前通常要写

```cpp
#include <string>
```

最基本的写法如下：

```cpp
std::string name;
std::cin >> name;
std::cout << "Hello, " << name << "!" << std::endl;
```

这里的 `name` 是一个 `string` 对象，`std::cin >> name` 表示从标准输入流中读入一个**连续的非空白字符串**。也就是说，如果输入是 `Xiao Ming`，那么 `>>` 默认只会先读到 `Xiao`，因为空格会被当作分隔符。这个特性以后会反复出现，因此最好现在就记住：**流输入运算符 `>>` 默认按空白分隔输入**。

把 `string` 看成对象之后，很多事情都会自然得多。比如说，字符串可以直接拼接：

```cpp
const std::string greeting = "Hello, " + name + "!";
```

这句代码之所以成立，是因为标准库已经为 `string` 定义好了合适的加法操作。这里就涉及三个非常重要的概念。

第一是**初始化**。`greeting` 在定义的同时就获得了初值，这和先定义、后赋值是两件不同的事。第二是**重载**（overload）。平时看到 `+`，常常会想到整数相加、实数相加；在这里，`+` 被赋予了适用于字符串的含义，即“把左边和右边的字符序列连接起来”。第三是**常量**。前面的 `const` 表示 `greeting` 一旦初始化完成，后面就不再允许被修改。

对初学者来说，这里最值得建立的观念是：在 C++ 里，许多熟悉的符号并不只服务于基本类型。只要某个类型被设计得足够完整，它也可以像整数、浮点数那样参与表达式。这正是“把数据和操作组织到一起”的一种体现。

### 1.4 构造函数、成员函数与 `size()`

当看到下面这些语句时：

```cpp
std::string name;
std::string hello = "Hello";
std::string first(10, '*');
```

读者会发现它们虽然都在“定义字符串”，写法却不完全一样。这是因为 `string` 作为一个类类型，可以通过不同方式构造出不同状态的对象。

最简单的 `std::string name;` 表示创建一个空字符串。`std::string hello = "Hello";` 表示用字面量 `"Hello"` 来初始化对象。`std::string first(10, '*');` 则表示构造一个由 10 个 `'*'` 组成的字符串。这里的这种“定义对象时顺便调用某种特殊初始化方式”的机制，正是**构造函数**（constructor）在起作用。

与之相配套的，还有**成员函数**（member function）。成员函数可以理解为“属于某个对象自己的函数”。例如：

```cpp
greeting.size()
```

中的 `size()` 就是 `string` 的成员函数，它返回字符串中字符的个数。写成 `greeting.size()`，意思是“向对象 `greeting` 询问它自己的长度”。这种写法和普通函数调用不同，普通函数像 `sort(a, b)` 那样把对象作为参数传进去；成员函数则是“由对象自己发起操作”。

当写出下面两句时：

```cpp
const std::string spaces(greeting.size(), ' ');
const std::string first(second.size(), '*');
```

程序的意思其实很直观。先取 `greeting` 的长度，再构造一个同样长、内容全是空格的字符串 `spaces`；接着根据另一行的长度，再构造一个由若干个星号组成的边框。这里 `size()` 返回的是长度，构造函数负责“按给定个数重复某个字符”。只要能把这两种机制区分清楚，类似写法以后都会很好理解。

### 1.5 用字符串拼出一个装框问候语

`string` 的一个很自然的练习，是生成一个带边框的问候语。例如想得到这样的输出：

```text
********************
*                  *
* Hello, XiaoMing! *
*                  *
********************
```

如果直接一行一行手写，当然也能做出来，但那样做的程序几乎没有通用性。一旦名字长度变了，边框宽度就不对了。更合理的思路是先把中间真正要显示的问候语构造出来，再根据它的长度自动生成上下边框和空白行。

一种典型写法如下：

```cpp
const std::string greeting = "Hello, " + name + "!";
const std::string spaces(greeting.size(), ' ');
const std::string second = "* " + spaces + " *";
const std::string first(second.size(), '*');
```

这几句很值得反复体会。程序不是在“画图”，而是在**先构造若干有意义的字符串对象**。`greeting` 是真正的问候语；`spaces` 是一串和问候语一样长的空格；`second` 是中间空白行；`first` 是由星号组成的顶部和底部边框。等这些对象都准备好之后，输出就会变得非常机械：

```cpp
std::cout << first << std::endl;
std::cout << second << std::endl;
std::cout << "* " << greeting << " *" << std::endl;
std::cout << second << std::endl;
std::cout << first << std::endl;
```

这个例子看似简单，却体现了非常重要的程序设计思想：**不要急着输出，先把将要输出的内容组织清楚**。也就是说，程序并不只是“按顺序写几条命令”，更是在中间构造合适的数据，再让输出阶段自然发生。后面学类和对象时，这种“先组织数据，再调用操作”的思路会越来越重要。

### 1.6 `auto`、常见定义方式与“类型推断”

在 C++ 中，变量并不总要把完整类型手写出来。有些场合可以用 `auto` 让编译器自己推断类型。例如：

```cpp
auto size = greeting.size();
```

这句的意思是：把右边表达式的类型交给编译器判断，然后用这个类型去定义左边的变量 `size`。这样做的好处是，当右边类型较长、较复杂，或者根本不方便手写时，代码会简洁很多。

不过，`auto` 不是“万能偷懒”。它的前提是右边必须已经给出了足够明确的初值。例如：

```cpp
auto hello = "Hello";
```

这里推断出的并不是 `std::string`，而是更接近字符串字面量底层形式的类型。如果想得到真正的 `string` 对象，就必须非常清楚右边到底是什么。因此，入门阶段对 `auto` 的态度最好是：**把它当作方便工具，而不是避免理解类型的借口**。当右边类型很明确时可以使用；当右边类型本身就容易让人糊涂时，直接把类型写出来反而更稳妥。

### 1.7 当数据不止一个：为什么需要 `vector`

很多程序问题并不是只处理单个数值。例如，计算课程成绩时，期中和期末只有各一个分数，但作业成绩往往有一批。此时最自然的问题就是：这些作业分数该如何保存？

如果事先知道数据个数固定，那么用若干独立变量当然也能勉强处理；若个数很多，数组也能派上用场。但这里有一个关键困难：**在输入开始前，往往并不知道作业到底有多少次**。这时，固定长度的办法就很不灵活了。C++ 标准库给出的经典解决方案是 `vector`。

`vector` 是一种**顺序容器**（sequence container），也可以把它理解为一种“能自动增长的数组”。它里面的元素按线性顺序保存，可以通过位置访问对应元素，并且在需要时自动扩大自身容量。对于初学者来说，最重要的直观认识是：`vector` 既保留了数组“按下标访问”的方便，又避免了固定长度数组“不够大或浪费空间”的尴尬。

例如：

```cpp
std::vector<double> homework;
```

这表示定义一个空的 `vector`，里面准备存放 `double` 类型的元素。尖括号中的 `double` 告诉编译器：这个容器中每个位置保存的都是双精度浮点数。以后如果想保存字符串，也可以写成 `std::vector<std::string>`。

### 1.8 逐个读入数据：`push_back` 与流状态

定义好 `vector<double> homework;` 之后，下一步通常就是把输入的作业成绩一项项放进去。典型代码如下：

```cpp
double x;
std::vector<double> homework;
while (std::cin >> x) {
    homework.push_back(x);
}
```

这段代码非常重要，因为它体现了两个核心知识点。

第一个知识点是 `push_back`。这个成员函数的含义是：**把一个新元素追加到容器末尾**。每读入一个成绩，就把它放到 `homework` 的最后面去。这样程序根本不需要提前知道一共有多少个成绩，因为容器会自己增长。

第二个知识点是 `while (std::cin >> x)` 这种写法。很多初学者第一次看到时会有些困惑：为什么输入语句本身能放在 `while` 条件里？原因在于，流输入表达式不仅会尝试读入数据，还会返回流对象本身的状态。若读取成功，条件就为真；若读取失败，例如到达输入结束或遇到非法输入，条件就为假，循环自然结束。

这是一种非常地道的写法，因为它把“读取一个数据”和“检查是否还能继续读取”合并在了一起。于是程序结构十分紧凑，也不容易写出“多读一次”或者“少检查一次”的错误。

当程序需要通过键盘手工结束输入时，通常要给出一个文件结束标志。在 Windows 系统中，常见做法是按 `Ctrl+Z`；在一些其他系统中，则常见为 `Ctrl+D`。从程序员角度看，更重要的不是记住按键本身，而是理解：**输入结束本身也是一种信号，流状态会据此变成失败，从而结束循环**。

### 1.9 `vector` 的大小、下标与 `size_type`

向 `vector` 中读完数据后，通常要先知道里面到底存了多少个元素。对应成员函数是

```cpp
homework.size()
```

它返回当前元素个数。例如：

```cpp
auto size = homework.size();
```

或

```cpp
std::vector<double>::size_type size = homework.size();
```

都可以用来保存结果。

这里为什么会出现看上去有些长的 `std::vector<double>::size_type`？原因在于，不同容器用于表示“长度”或“下标”的类型，理论上可以由它自己决定。标准库提供 `size_type`，就是在告诉程序员：“如果你要保存这个容器的大小，最好使用我自己推荐的类型。” 这样可以减少类型不匹配带来的隐患。

有时也会写成

```cpp
typedef std::vector<double>::size_type vec_sz;
vec_sz size = homework.size();
```

这表示给这个很长的类型起一个别名 `vec_sz`，以便后面重复使用。现代写法中，`auto` 往往更简洁，但知道 `size_type` 的存在仍然很重要，因为它体现了标准库容器“自己定义合适的相关类型”这一设计风格。

当需要访问第 `i` 个元素时，可以写

```cpp
homework[i]
```

这说明 `vector` 支持按位置直接访问，这也是它和链表等其他容器相比的一个明显特点。不过，使用下标访问之前必须非常小心：只有当下标确实落在合法范围内时，这种访问才有意义。也就是说，若容器大小是 `size`，那么合法下标应当从 `0` 到 `size-1`。

### 1.10 为什么要先判断“有没有数据”

考虑这样一种情况：程序准备根据作业成绩计算中值，但用户根本没有输入任何作业分数。如果此时仍然强行取“中间元素”，程序就会立刻失去依据。于是，在真正排序和取中值之前，先检查 `vector` 是否为空，就是一件非常必要的事。

最直接的写法是：

```cpp
if (size == 0) {
    std::cout << "You must enter your grades." << std::endl;
    return 1;
}
```

这里的逻辑很简单：若元素个数为 0，就说明没有作业成绩，于是程序输出提示并提前结束。初学程序设计时，很多人容易把注意力全部放到“主要算法”上，却忽略“输入根本不满足前提怎么办”。事实上，程序真正稳不稳，往往就体现在这种前提检查上。

从更一般的角度说，编写程序时应该逐渐形成一个习惯：**在使用某个数据结构之前，先确认它确实处于可以被使用的状态**。对于 `vector` 来说，取下标前最好先知道它非空；对于输入流来说，使用读取结果前要先知道读取成功；对于字符串来说，拼接前要先知道对象已经被正确定义。这种思路后面会不断出现。

### 1.11 排序：从无序数据到有序数据

若想计算一批数据的中值，最自然的前提就是先把它们按从小到大的顺序排好。C++ 标准库提供了现成的排序算法 `sort`，定义在头文件 `<algorithm>` 中。因此使用前通常要写

```cpp
#include <algorithm>
```

排序的典型写法是：

```cpp
sort(homework.begin(), homework.end());
```

这里最值得解释的是 `begin()` 和 `end()`。它们不是“第一个元素”和“最后一个元素”，而是两个**位置**。`begin()` 表示第一个元素所在的位置，`end()` 表示最后一个元素之后的位置。标准库算法经常使用这种半开区间 `[begin, end)` 的记法，即包含左端、不包含右端。这样设计的好处是：区间长度可以直接由两个位置的关系确定，而且空区间也更容易表达。

于是，`sort(homework.begin(), homework.end())` 的含义就是：对整个容器中的元素进行非递减排序。这里的“非递减”可以理解为从小到大排列，允许相邻元素相等。

对初学者来说，`sort` 的重要性不只在于“它能用”，更在于它体现了 C++ 标准库的组织方式：**容器负责保存数据，算法负责处理数据，而算法通过位置范围来工作**。也就是说，`vector` 不一定自己带排序功能，但它可以把自己的元素范围交给标准算法 `sort` 去处理。这种“容器与算法分工”的思想，在后面还会不断出现。

### 1.12 平均值与中值：为什么有时要改用中值

在一批作业成绩中，最直接的统计量是平均值。但平均值有一个明显弱点：它很容易受到极端值影响。若某次作业因缺交而出现一个特别低的分数，或者某次录入错误导致一个特别高的分数，平均值就会被明显拉偏。

这时可以引入另一个重要概念：**中值**（median）。中值是指把数据排序之后，位于正中间的那个值。若数据个数为奇数，中值就是最中间的一个元素；若数据个数为偶数，中值通常取中间两个元素的平均值。

设容器大小为 `size`，则中间位置通常记作

```cpp
vec_sz mid = size / 2;
```

然后中值可以写成

```cpp
double median = size % 2 == 0
              ? (homework[mid] + homework[mid - 1]) / 2
              : homework[mid];
```

这里用到了**条件运算符** `?:`。若 `size % 2 == 0` 为真，说明元素个数为偶数，就取中间两个元素的平均值；否则直接取中间那个元素。这个表达式之所以成立，前提正是前面已经调用过 `sort`，因此 `homework` 里的元素已经按顺序排列好了。

需要特别注意两点。第一，`size / 2` 在整数语境中表示整除，因此例如 `5 / 2` 的结果是 `2`，这正好对应下标从 0 开始时的中间位置。第二，若没有先排序，所谓“中间元素”就毫无统计意义。也就是说，**中值不是原数据中按输入顺序排在中间的那个数，而是排序后排在中间的那个数**。

### 1.13 输出精度：为什么成绩不能随便打印

程序算出成绩之后，往往还要控制输出格式。例如，希望结果保留 3 位有效数字时，可以写

```cpp
std::cout << std::setprecision(3) << value;
```

与之相关的头文件通常是 `<iomanip>`。`setprecision` 的作用是修改输出流的精度设置，使后续输出按指定精度显示。

有时程序并不想永久改变精度，而只是暂时改一下，输出完结果之后再恢复原状。这时可以先保存旧精度：

```cpp
std::streamsize prec = std::cout.precision();
```

然后输出时临时设置新精度，最后再恢复：

```cpp
std::cout << std::setprecision(3) << value
          << std::setprecision(prec);
```

这里的 `streamsize` 是与流精度相关的类型。入门阶段不必过度追究它的底层细节，但要知道：既然标准库提供了专门的类型，就最好顺着它的设计去写。

若想固定保留若干位小数，还可以配合

```cpp
std::cout.setf(std::ios::fixed);
std::cout << std::setprecision(1);
```

一起使用。这样输出 `3.14159` 时，就会更接近“保留 1 位小数”的效果，而不是简单地控制有效数字个数。

### 1.14 一个完整例子：计算课程成绩

把前面的内容合到一起，就会得到一个很有代表性的完整程序：先输入姓名，再输入期中和期末成绩，再读入一批作业成绩，把它们保存到 `vector` 中，排序后取中值，最后按指定精度输出总评成绩。

这类程序的核心框架大致如下：

```cpp
std::string name;
std::cin >> name;

double midterm, final;
std::cin >> midterm >> final;

double x;
std::vector<double> homework;
while (std::cin >> x) {
    homework.push_back(x);
}

auto size = homework.size();
if (size == 0) {
    return 1;
}

sort(homework.begin(), homework.end());
auto mid = size / 2;
double median = size % 2 == 0
              ? (homework[mid] + homework[mid - 1]) / 2
              : homework[mid];

double result = 0.2 * midterm + 0.4 * final + 0.4 * median;
```

这段程序之所以重要，不只是因为它能算一个成绩，更因为它把本章的许多知识点都串了起来。字符串用于保存名字；输入输出流负责与用户交互；`vector` 用于保存数量不定的一批作业成绩；`push_back` 负责追加元素；`size()` 用于获得容器大小；`sort` 负责排序；下标访问用于取中间元素；条件运算符用于区分奇偶情形；`setprecision` 用于控制最终输出格式。

从学习路径上看，这正是一种非常典型的 C++ 入门方式：先不急着进入复杂的类设计，而是先学会借助标准库写出结构清晰、数据组织自然的小程序。把这一关过稳了，后面学习类、成员函数、运算符重载和模板时，才不会总被最基本的容器和输入输出绊住。

### 1.15 本章小结

这一章真正要建立起来的，不只是若干语法点，而是一种新的程序组织习惯。文本应当优先交给 `string` 处理，而不是急着退回字符数组；若数据个数未知，就应当考虑 `vector` 这样的动态容器；容器中的数据可以交给标准库算法处理，而不是每件事都自己从头写；输入不仅仅是“读值”，还要顺手检查流状态；输出不仅仅是“打印结果”，还要考虑精度和格式。

如果把这些内容贯通起来，可以把本章概括为一句话：**C++ 程序设计的基础，不在于记住更多零散语法，而在于学会借助库中的对象、容器和算法，更自然地表达问题。**

### 本章小练习

1. 填空题  
若已经定义 `std::string name;`，并希望从标准输入中读入一个名字，应写：`__________`。

2. 简答题  
为什么在计算一批作业成绩的中值之前，必须先排序？

3. 程序题  
设 `std::vector<double> v;` 中已经保存了一批成绩。请写出一条语句，把分数 `95.5` 追加到容器末尾；再写出一条语句，对整个容器按从小到大排序。

### 参考解答

1. 可以写为

```cpp
std::cin >> name;
```

这里 `std::cin` 是标准输入流，`>>` 是输入运算符，它会把读到的非空白字符串保存到 `name` 中。

2. 因为中值的定义依赖于“排好序之后位于中间位置的数”。如果原数据没有排序，那么所谓“第几个元素”只反映输入顺序，而不反映数值大小关系，此时取出的“中间元素”并不是统计学意义上的中值。

3. 追加元素可以写为

```cpp
v.push_back(95.5);
```

排序可以写为

```cpp
sort(v.begin(), v.end());
```

第一句调用的是 `vector` 的成员函数 `push_back`，第二句调用的是标准库算法 `sort`，其中 `v.begin()` 与 `v.end()` 给出了整个容器对应的位置范围。
